解説ポイント（必ず守ること）
レスポンシブ列数

grid-cols-2（スマホ最小：2列）→ sm:grid-cols-3 → md:grid-cols-4 → lg:grid-cols-6 → xl:grid-cols-8

これにより、画面幅に応じて 2～8列でロゴを配置し、常に十分な余白と潰れないサイズを維持。

余白設定

セクション全体のパディング：py-24 → px-6 sm:px-8 md:px-12 を wrapper に入れ、左右の余白を十分に確保。

gap-8 でロゴ同士の隙間を 2rem（32px） 確保。

ホバーエフェクト

filter grayscale を付与しておき、hover:filter-none でカラー化。

hover:scale-105 transition-all duration-200 で微妙に拡大。

マウスオーバー時にのみ動作するように、group を使わずとも hover: で完結。

アクセシビリティ

<a> タグに aria-label を明記。視覚的テキストがない場合でもスクリーンリーダーが読み上げられるようにする。

rel="noopener noreferrer" を付与してセキュリティを担保。

画像読み込み最適化

<img loading="lazy"> あるいは Next.js の <Image loading="lazy"> を使い、初期ロードを軽量化。

ID属性

セクションに id="tech-partners" を入れておくことで、ナビリンクや「トップへ戻る」などのアンカー移動が可能。

<header> / <nav>

2.2 レスポンシブ＆レイアウト
全体コンテナの幅管理

統一して container mx-auto を使わず、独自に max-w-6xl mx-auto px-6 sm:px-8 lg:px-12 などで制御。

画面幅ごとに左右余白が崩れていないかチェック（特に md, lg, xl）。

フォントサイズ

h1: text-5xl md:text-6xl lg:text-7xl

h2: text-3xl md:text-4xl

h3: text-2xl md:text-3xl

本文：text-base md:text-lg

モバイルフォントはビューポート幅に依存させない（vw 検討不可）。すべて Tailwind の text-* で明示的に指定。

グリッドレイアウト

すべてのグリッドは少なくとも gap-6 〜 gap-8 を使用し、要素が潰れないように調整。

テーブル系（About セクション）のスマホ縦スクロール時に崩れないよう、<div className="overflow-x-auto"> で囲むこと。

画像・動画のアスペクト比保持

object-contain をすべての <img> や <video> に付与。

ロゴやアイコンには必ず高さを h-10 sm:h-12 md:h-14 lg:h-16 のように段階指定し、幅は自動（w-auto）か max-w-full とする。

Skip Link

ARIA ランドマーク

<header role="banner">, <nav role="navigation">, <main role="main" id="main">, <footer role="contentinfo"> を確実に付与。

各セクションも role="region" aria-labelledby="～" を付与。

フォーム

<label> と <input id="..."> による紐付けを必須とし、aria-required="true" を入力必須フィールドに付与。

送信時にエラーがある場合は、該当フィールドに aria-invalid="true" かつ role="alert" でエラーを読み上げさせる。

キーボードナビ

すべてのボタン／リンクは :focus:outline-none focus:ring-2 focus:ring-offset-2 focus:ring-primary を持つ。

ハンバーガーメニューはキーボードで開閉できる（Enter/Space キーを使う）。

FAQ の Accordion は、キーボードで開閉できるように tabIndex="0" と aria-expanded の更新を行う。

コントラスト比チェック

テキスト(白, グレー) vs 背景(#0F0F0F, #1A1A1A) のコントラスト比は最低 4.5:1 以上。

Lighthouse の「Accessibility」セクションで 100 点を目指す。

2.10 レンダリングとテスト
ブラウザ互換性チェック

最新バージョンの Chrome, Firefox, Safari, Edge でサイトを動作確認し、レイアウト崩れやホバーエフェクトが同一かをチェック。

モバイル実機（iOS Safari, iPhone 挙動、Android Chrome）でも自動再生・レイアウト・フォーム挙動を細かく確認。

Lighthouse スコア

Lighthouse で「Performance」「Accessibility」「Best Practices」「SEO」のすべてを 90 点以上に調整。

必要であれば、next/image の priority と layout="responsive" を使用し、LCP（Largest Contentful Paint）を改善。

Visual Regression Testing

Chromatic または Percy で「Tech Partners セクション」「Heroセクション」「フォーム」など主要パーツのスナップショットを作成。

CI 実行時に自動チェックを行い、差分が出た場合は Slack やメールでレポート。

アクセシビリティ自動テスト

axe-core を Jest + Puppeteer などで組み込み、自動テストに合格しないとマージできないルールを設定。
